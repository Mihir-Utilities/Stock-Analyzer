B10 reads this document.
- **D04-A3 Risk window.** Volatility, max drawdown and Sharpe use the 3Y window (the NAV on or before end-3Y is the baseline); with less than 3Y but at least 1Y, the full history; under 1Y all null. Sharpe is null unless the window is a full 3Y. Max drawdown has no stated window in docs/05 9.3; the vol window is used. Median gap > 3 days nulls volatility and Sharpe (reason `weekly_nav`).
- **D04-A4 Inactive rule (MF-06, MF-18)** (docs/04 3.6 says "absent for 60 days" but there is no absent-since column and no migration was added): a scheme is `inactive` when the freshest of its AMFI value date and its stored `last_nav_date` is missing or older than 60 days, otherwise `active`. Status changes only in a run where the AMFI file parsed; a failed download or bad header never changes status (MF-19).
- **D04-A5 List page size** follows MF-18/S6 (`limit=10000`, until an empty page), not the older `limit=1000` in docs/04 3.6.
- **D04-A6 AMFI fallback** writes the AMFI latest NAV into `mf_nav` with its own value date (no source column exists; S6 showed identical values). The run is `partial` with reason `mfapi_unavailable_amfi_fallback`, and the codes are listed in `details.amfi_fallback`.
- **D04-A7 Incremental window:** `startDate = last_nav_date + 1`, `endDate = today (IST)`; the call is skipped when the start is after today. A mfapi NAV with a value date after today is picked up by a later run.
- **D04-A8** The `mf_refresh` worker-http handler (target = scheme code) was added because the allow-listed kind otherwise answers 501; it reuses the ingest code for one scheme.
- **D04-A9** `AMFI_MIN_INTERVAL_SEC` is not a setting (one download per run); the limiter floor is 1 s.
